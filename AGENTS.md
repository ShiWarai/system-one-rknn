# Инструкции для агента

Репозиторий — шаблон сервиса service-template. CI, compose и заглушки уже есть. Новое поведение добавляй кодом, а не описанием.

## Порядок работы

1. Сначала код реальной функции. Заглушки `scripts/stub-server.sh` и `scripts/ci-test.sh` замени, как только появляется свой процесс и свой набор тестов.
2. К той же правке добавь тесты, которые вызывают эту функцию. Юнит — реальные входы и выходы, включая пустой ввод и ошибку. Интеграционный — реальная граница снаружи: HTTP-ручка, CLI или dev-контейнер. Фикстуры клади в `tests/`, не в прод-образ. Тест, который проверяет только вызов мока, подменяет саму проверяемую функцию или просто завершается с кодом 0, не считается покрытием. `echo ok` в `scripts/ci-test.sh` допустим только пока в репозитории нет кода приложения.
3. После правок кода, зависимостей или Dockerfile прогони линтер проекта и `docker compose -f docker-compose.dev.yml run --rm -T dev ./scripts/ci-test.sh`. Линтер и тестовые зависимости ставь в target `dev`, не в `runtime`. Ошибку линтера не оставляй. Как только появляется язык, линтер входит в `scripts/ci-test.sh`.
4. `README.md` и `docs/` не меняй по ходу задачи. Обновляй их только когда пользователь просит коммит, и только если сменились команды, порт, переменные `.env.example`, публичный API или команда тестов. Файл целиком не переписывай и не добавляй разделы, которых нет в diff.
5. Коммит и push — только по явной просьбе. Секреты не коммить: образец живёт в `.env.example`.

## Образ

Ориентир — корневой `Dockerfile`: target `dev` и `runtime` от `debian:bookworm-slim`. База с именем и тегом, не `latest`.

- В `runtime` только пакеты, без которых процесс не стартует. Компилятор, git, линтер, тестовый раннер и кэши пакетного менеджера остаются в `dev`.
- Один слой установки: `apt-get update && apt-get install -y --no-install-recommends … && rm -rf /var/lib/apt/lists/*`. Для pip — `--no-cache-dir`, для npm — `npm ci` по lock-файлу.
- Сначала копируй только манифест зависимостей и ставь их, потом исходники. В финальный образ копируй артефакт, не весь репозиторий. Ставь то, что импортирует код, не весь стек «на будущее».
- Секреты не клади в `ENV` и не копируй `.env`. `.dockerignore` оставляет за бортом `.git`, `.github`, `docs`, `.env`, `models/`.
- Healthcheck бьёт в живую ручку. Оверлеи `docker-compose.prerelease.yml` и `docker-compose.prod.yml` оставляй с `build: !reset null`: в Compose 5.1 `!override null` не снимает сборку.
- Устройства NPU и тома моделей добавляй только если сервис ими пользуется.
- Не ломай развилку Deploy → `:prerelease` → Publish, теги GHCR и матрицу `linux/amd64` / `linux/arm64`.
